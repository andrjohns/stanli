# stanrt M1 (spine) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An in-process op-graph executor over precompiled stan-math kernels that reproduces stan-math var gradients bitwise on hand-built model graphs (eight schools, logistic GLM) and samples them with NUTS.

**Architecture:** Structured op graph executed forward/backward over flat double arenas. Native ops stash double partials forward (recorder kernels reuse unmodified stan-math density templates via a custom scalar); legacy ops replay through a nested var tape. NUTS comes from vendored stan-dev/stan driven through a model adapter that wraps our gradient in `precomputed_gradients`.

**Tech Stack:** C++17, CMake + ctest (no test framework dependency), vendored stan-math + stan at pinned SHAs, clang on macOS arm64 (primary), single-threaded.

## Global Constraints

- Gradient parity vs the var path: bitwise where achievable; otherwise <= 2 ULP with a comment justifying the divergence at the assertion site.
- Zero heap allocation in steady-state `forward()`/`backward()` (allocations only at bind time).
- stan-math sources are never modified; all adaptation happens in our headers.
- All densities instantiated `propto=false` in M1 (matches `target += dist_lpdf(...)` semantics). propto variants are M2.
- Kernels are all-`rvar` instantiations; data/parameter distinction is runtime-only (executor contracts only parameter partials).
- No em-dashes, no "genuinely", no "load-bearing" in committed text. No AI attribution in commits.
- Commit after every green test cycle.

## Reference: vendored dependency layout

`deps/fetch.sh` clones into `deps/math` and `deps/stan` (gitignored) with
sparse checkout. All CMake include paths below assume it has run:

- `deps/math` (stan-dev/math, pinned): `stan/`, `lib/eigen_*`, `lib/boost_*`, `lib/sundials_*/include`, `lib/tbb_*/include`
- `deps/stan` (stan-dev/stan, pinned): `src/stan/mcmc`, `src/stan/model` (headers only; we compile nothing from it except what we include)

Required compile flags everywhere stan-math is included:
`-std=c++17 -D_REENTRANT -DBOOST_DISABLE_ASSERTS` plus the include dirs above.
Link tests against `tests/tbb_stub.cpp` (single-threaded; stubs the one TBB
observer symbol stan-math's rev core references on macOS).

```bash
#!/usr/bin/env bash
set -euo pipefail
cd "$(dirname "$0")"
fetch() { # name url sha sparse...
  local name=$1 url=$2 sha=$3; shift 3
  if [ ! -d "$name/.git" ]; then
    git clone --filter=blob:none --sparse "$url" "$name"
  fi
  git -C "$name" sparse-checkout set "$@"
  git -C "$name" fetch -q origin "$sha" && git -C "$name" checkout -q "$sha"
}
fetch math https://github.com/stan-dev/math.git <MATH_SHA> stan lib
fetch stan https://github.com/stan-dev/stan.git <STAN_SHA> src/stan
```

**Files:**

**Interfaces (produced, used by every later task):**

```cpp
namespace stanrt {
struct Desc { double* data; int64_t len; };          // len==1 => scalar
struct Slot { int64_t offset, len; bool is_param; };
struct Op {
  uint16_t opcode;
  int out;                    // slot index
  int in[6]; int n_in;
  const int* idata; int64_t n_idata;   // integer immediates (counts etc.)
  int64_t scratch_off, scratch_len;    // into graph scratch arena
};
struct KernelCtx {            // view assembled by the executor per call
  Desc in[6]; int n_in;
  Desc out;
  double* scratch;
  const int* idata;
  Desc in_adj[6];             // data slots get {nullptr,len}
  double out_adj;             // M1: all op outputs are scalar lp terms or
                              // vector slots; vector-out ops read out_adj_vec
  Desc out_adj_vec;
};
struct Kernel {
  void (*forward)(KernelCtx&);
  void (*backward)(KernelCtx&);
  int64_t (*scratch_size)(const Op&, const Slot* slots);
};
Kernel& kernel(uint16_t opcode);          // registry, optable.hpp
struct Graph {                            // built programmatically in M1
  std::vector<Slot> slots; std::vector<Op> ops;
  int result_slot;                        // scalar lp
  int add_slot(int64_t len, bool is_param);
  int add_op(uint16_t opcode, std::initializer_list<int> ins, int out,
             std::vector<int> idata = {});
};
class Executor {
 public:
  explicit Executor(Graph g);             // sizes arenas + scratch, binds
  double* param_ptr(int slot); double* value_ptr(int slot);
  double forward();                       // returns value of result_slot
  double gradient(double* grad_out);      // forward + backward; grad in
                                          // param-slot declaration order
  int64_t n_params() const;
};
}  // namespace stanrt
```

(out[i] = a + b*x[i]; backward: da += sum(dout), db += dot(dout, x),
dx[i] += b*dout[i]).

### Task 4: Recorder density kernels

**Files:**
- Create: `runtime/kernels/densities.cpp`, `runtime/include/stanrt/densities.hpp`
- Test: `tests/test_densities.cpp`

**Interfaces:**
- Produces opcodes + kernels, all signatures `(y, args...) -> scalar lp`, every real argument accepted as scalar-or-vector Desc at runtime where stan-math's template allows broadcasting:
  `OP_NORMAL_LPDF(y, mu, sigma)`, `OP_CAUCHY_LPDF`, `OP_STUDENT_T_LPDF(y, nu, mu, sigma)`, `OP_GAMMA_LPDF(y, alpha, beta)`, `OP_BETA_LPDF`, `OP_POISSON_LOG_LPMF(idata=n; alpha)`, `OP_BERNOULLI_LOGIT_LPMF(idata=n; alpha)`.
- Edge maps are fixed per function (all-rvar instantiation): integer outcomes are not edges, so e.g. poisson_log has one edge (alpha) at index 0.
- Kernel forward: map Descs via `as_rvar` (scalar Descs to `rvar` by value), set sink bufs into scratch (contiguous per-edge segments in operand order), call the lpdf, write `s.value` to out. Backward: for each edge whose Desc is a parameter slot, `in_adj[k][i] += out_adj * scratch_edge_k[i]` (scalar edges accumulate the single partial; a scalar edge paired against a vector y accumulates the broadcast sum stan-math already folded into that single partial).
- `scratch_size` = sum of operand lens over edges.

- [ ] **Step 1: Write tests/test_densities.cpp** (RED): for each of the seven densities, build a one-op graph, run `gradient()`, and compare value + every parameter gradient bitwise against an in-process var-path evaluation of the same call (structure copied from the spike's multi.cpp, including a data-argument case for normal and student_t and both scalar and vector mu for normal).
- [ ] **Step 2: Run, verify failure.**
- [ ] **Step 3: Implement densities.cpp** (one function template + seven explicit wrappers; poisson/bernoulli read counts from `idata`).
- [ ] **Step 4: Run, verify PASS (bitwise, all cases).**
